## Decision and exact delta

`a16-prototype-b-r3` is the sole authorized continuation from immutable failed r2. Exact signed
root and source provenance prove r2's first causal error was generated by one object:

```text
r4 /vendor: directory, 0755, uid/gid 0:2000, u:object_r:vendor_file:s0
r2 /vendor: symlink -> /system/vendor, 0644, uid/gid 0:0,
            u:object_r:vendor_file:s0
```

The r3 signed system tree relative to r2 is exactly `added=[]`, `removed=[]`,
`changed=[vendor]`. R3 replaces that symlink with the empty r4 directory contract. Android and
kernel were not rebuilt; the preserved mixed-system build number remains `UBOX10_A16_QPR0_B1`.

## Proven root cause

The exact vendor_boot first-stage fstab is byte-identical across r4/r2/r3, SHA-256
`6C771313A6F9DEDAEFA4061B14FE142F050F4AB13D360FF2F60FB9361277F701`, and contains:

```text
vendor /vendor ext4 ro,barrier=1 wait,first_stage_mount,logical,slotselect
```

The executed first-stage init is also byte-identical, ELF32 ARM, SHA-256
`2A7D6E125583C79E925B5D916C54C51E4AE8EE145F2D7422B2DD77D0B6C62751`. Its
`MountPartition()` calls `fs_mgr_create_canonical_mount_point()` before mapping and mounting the
logical partition; that function requires `realpath(mount_point) == mount_point`. R2 therefore
maps `/vendor` to `/system/vendor`, logs the observed noncanonical error and returns failure before
second-stage init. The retained Android 12 system/core source object at commit `1d37c449...0ce3`
contains this exact control flow and UART string (`fs_mgr.cpp` SHA-256 `845804B5...C2F`,
`first_stage_mount.cpp` `4EEF3E55...17B`); its fstab parser (`2DC4C621...993`) also applies the
same `/system/system_ext/etc/init/config/skip_mount.cfg` before remaining mounts. This source is
corroboration for the independently byte-pinned executable, not a claim that a missing vendor build
manifest was recovered.

Generation provenance is exact. R4 uses `PRODUCT_DEVICE=generic`, whose GSI BoardConfig chain sets
`TARGET_COPY_OUT_VENDOR=vendor` and `BOARD_VENDORIMAGE_FILE_SYSTEM_TYPE=ext4`; this makes
`BOARD_USES_VENDORIMAGE=true`, and `create_root_structure.mk` creates a root directory. B1/B2 use
the dedicated `ubox10_ceiling_arm64` BoardConfig, which inherits plain
`device/generic/arm64/BoardConfig.mk` without those GSI settings. `TARGET_COPY_OUT_VENDOR`
therefore defaults to `system/vendor`, `BOARD_USES_VENDORIMAGE` remains false, and the same root
rule emits `/vendor -> /system/vendor`. This uniquely explains the signed image difference and the
UART `realpath()` result.
