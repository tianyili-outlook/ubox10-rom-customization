# UBOX10 UART 被动监听手册（FT232RL / 只收不发）

## 适用范围与风险等级

本手册只用于收集启动日志，不用于登录、打断 U-Boot、发送命令或刷写。

- **被动接收接线**：低风险；只接地和板端 TX，适配器不会向板子供电或发送电平。
- **错误接线/不明针脚**：中风险；可能短路、反灌电源或向错误引脚施加电压。
- **主动 TX、VCC、短接启动脚**：高风险；当前阶段禁止。

J21 的针脚标签已由 2026-07-25 的实物照片确认：按归档照片方向从左到右为 `GND`、`TX`、`RX`。这只是丝印与外观验证，**不是电压或连续性测量**；实际接线必须按每个针脚旁的丝印，而不是脱离照片方向记忆“左/中/右”。

## 当前硬件状态（2026-07-25）

- 用户已购入 FTDI FT232RL USB-UART 模块，并报告 J21 串口已焊接。
- FT232RL 模块正反面和 J21 照片已归档于 `logs/device/20260725-uart-preflight/`；J21 丝印为 `GND/TX/RX`，顶面未见明显连锡，但 PCB 背面焊点未拍摄。
- FT232RL 模块的跳帽在照片中**视觉推断为 5V 档**。用户没有万用表，实际 VCCIO/逻辑电平仍未测量。
- 模块侧面有丝印清晰的 `GND` 与 `RXD` 孔位；底部六针排针的逐针定义未获可靠证据，首次实验禁止使用。
- 对任何**未来**的重采集，仍只允许执行下述“无万用表、输入端被动接收”路径；J21 背面焊点、跳帽位置和最终两线接线照片复核前不得给 UBOX10 通电。该要求不改写已经完成的 20260725-004019 历史记录。

FT232R 芯片的 UART 电平由 **VCCIO** 决定；官方数据手册允许 VCCIO 为 1.8–5.25V，并说明总线供电设计可将 VCCIO 接到 3V3OUT 以获得 3.3V 输出，或接到 VCC 获得 5V CMOS 输出。市售模块的“3.3V/5V”跳帽可能只切换电源输出，也可能切换 VCCIO，必须以模块原理图或实测确认，不能只看跳帽文字。

## U3.1 实际捕获结果（2026-07-25）

`logs/device/20260725-004019/` 已保存一次成功的只收不发捕获：`COM3`、115200、8N1、无流控、90 秒、15,173 字节，`DTR/RTS=false`。元数据中的接线正是本手册的两线拓扑；JSON、raw 和 text 三项 SHA-256 已复算一致。

这证明板端 TX、公共地、FT232RL RXD 与 COM3 的被动接收链路在该次实验中可用。它**不**证明跳帽实际控制了 VCCIO，也不替代万用表测量。日志已定位到启动失败，当前不要为“继续调试”而重新通电或增加 TXD/VCC 接线；下一步是离线分析 `metadata` 分区的格式化责任。

U3.2 的首轮离线审计现已确认当前 `work/boot.img`/`vendor_boot.img` 含历史调试注入，且尚不能证明其与设备实装内容相同。因此设备继续保持断电；后续先完成镜像来源审计，而不是再次捕获或向 UART 增加任何连线。

若已经结束采集但仍保持接线，安全拆线顺序为：先断开 UBOX10 原装电源并等待约 10 秒/指示灯熄灭，再拔 FT232RL 的电脑 USB，最后拆两根 UART 线。这样避免目标板 TX 在适配器未供电时继续驱动其输入。

## U3.0：通电前强制预检

1. UBOX10 断开原装电源及与电脑相连的 `sunxi` USB 数据线；取出 PhoenixCard/TF 卡。FT232RL 拔掉 USB-C；两者之间不保留任何导线。
2. 归档 FT232RL 正面、背面及 J21 丝印/焊接照片。当前证据位于 `logs/device/20260725-uart-preflight/`。
3. 确认适配器是 **TTL UART** 模块而不是带 MAX232 的 ±RS-232 模块。当前照片通过该项外观检查。
4. 在完全断电状态下，把模块的黑色跳帽从丝印 `5V` 一侧移动到 `3.3V` 一侧：按归档正面照片方向，应短接中针与右针，左针露出。移动后先拍照，不连接 UBOX10。
5. 电平确认二选一：
   - **A 路径（有万用表）**：适配器仅连接电脑、未连接 UBOX10，测量 `TXD` 对 `GND` 的空闲电压；约 3.3V 才继续，测完仍不接 `TXD`。
   - **B 路径（当前，无万用表）**：不能宣称电平已验证；仅允许让 FT232RL 的高阻 `RXD` 做输入。必须使用模块侧面丝印明确的 `RXD/GND`，不得猜测底部六针排针；FT232RL 的 `TXD` 和所有电源脚永久不接本次实验。
6. 不论使用哪条路径，FT232RL 的 `VCC/5V/3V3` 都不接 UBOX10。UBOX10 只使用自己的原装电源。
7. 没有万用表时，应目视检查 J21 背面三处焊点，确认没有 `GND–TX` 或 `TX–RX` 连锡，并归档近照。只有在无需拉扯天线、同轴线或脆弱排线时才翻板；不能安全接近时停止，不得强拆。
8. 两根线固定后，通电前拍一张能同时看清 J21 标签、两根线、模块 `GND/RXD` 标签和 `3.3V` 跳帽位置的全景照片；照片未复核前停止。

**风险等级：中（无表预检与接线阶段）；低（最终接线复核通过后的纯接收运行）。** B 路径降低风险的依据是适配器只有 RX 输入与目标 TX 相连，没有任何适配器输出或电源脚连接目标板；它不能替代电压测量，也不能保证数据可读。预检失败时的恢复就是拔掉 FT232RL USB 和 UBOX10 电源；不得通过试接 VCC 或 FT232RL TXD 判断电平。

## 所需物品

1. 具备 **3.3V TTL 逻辑**的 USB-UART 适配器：CP2102 或 FT232 优先；CH340 仅在明确支持 3.3V I/O 时使用。
2. 两根可靠杜邦线；J21 已焊接后仍需检查相邻焊点没有连锡、松动或裸线短路。当前模块侧面 `GND/RXD` 孔位没有排针，若杜邦线无法稳定连接，应在完全断电时只为这两个孔焊接针脚或短引线；不得悬挂裸线试接。
3. 本仓库的 `scripts/capture-uart-readonly.ps1`；无需安装第三方终端软件。

绝不可使用传统 USB-to-RS-232 适配器（其信号可能为正负十余伏），不可使用 5V TTL，不可接适配器的 VCC 引脚。没有万用表时，仍可使用高阻的适配器 RX 做被动接收；不要因此猜测或连接电源/主机 TX。

本项目这块 FT232RL 模块的底部六针排针虽然已安装，但现有照片无法可靠证明逐针定义。首次实验只使用右侧扩展孔中丝印明确的 `GND` 和 `RXD`；底部六针全部不接。

如果 J21 是未焊的焊盘：不要用裸线、鳄鱼夹或探针在相邻焊盘间悬挂接触。优先使用稳定的 pogo pin 夹具；若无法稳定固定，停止并记录为硬件阻塞，而不是冒险试接。

## 首次接线：只接收

先给 UBOX10 **断电**，再按下图接线：

```text
UBOX10 J21 GND  ───────── FT232RL 侧面 GND
UBOX10 J21 TX   ───────── FT232RL 侧面 RXD

UBOX10 J21 RX   ────────  不连接
UBOX10 3.3V/VCC ────────  不连接
FT232RL TXD     ────────  不连接
FT232RL VCC/5V/3V3 ─────  不连接
FT232RL 底部六针 ───────  全部不连接
```

这条接线的恢复方式就是拔掉两根线。其目的只是让适配器观察板端发送的数据；它不能控制设备，也不应改变 USB/启动状态。

## U3.1：首次冷启动捕获

1. 按“首次接线”完成两根线并通过最终接线照片复核后，再把 FT232RL 插入电脑；UBOX10 此时仍断电。
   首次基线采集期间不要同时把 UBOX10 的 USB 数据口接到电脑，也不要插入 PhoenixCard/TF 卡，避免改变启动路径或形成第二条 USB 接地路径。HDMI 若保留用于观察屏幕，应在采集元数据中说明。
2. 在任意 PowerShell 目录都可以先执行只读 COM 枚举：

   ```powershell
   [System.IO.Ports.SerialPort]::GetPortNames()
   Get-CimInstance Win32_SerialPort | Select-Object DeviceID,Name,PNPDeviceID
   ```

3. 找到 FT232RL 对应的实际端口，例如 `COM3`。若无法唯一确认，先在 UBOX10 断电且未接线时拔掉 FT232RL USB，记录端口列表，再插入 FT232RL 并重新枚举；新增项才是候选。不要猜端口，也不要把字符串 `COMx` 原样输入。
4. 先切换到项目根目录并验证脚本存在。无论当前提示符是否位于 `C:\Windows\System32`，都执行：

   ```powershell
   Set-Location -LiteralPath 'C:\Users\tiany\Documents\ubox10-rom改造'
   Test-Path -LiteralPath '.\scripts\capture-uart-readonly.ps1'
   ```

   只有 `Test-Path` 返回 `True` 才继续。随后启动 90 秒采集器，把示例 `COM3` 替换为经拔插确认的实际端口：

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass `
     -File 'C:\Users\tiany\Documents\ubox10-rom改造\scripts\capture-uart-readonly.ps1' `
     -PortName COM3 -BaudRate 115200 -DurationSeconds 90 `
     -ReceiveOnlyWiringConfirmed
   ```

   脚本默认将证据写入仓库的 `logs/device/<run-id>/`，不再依赖调用时的当前工作目录。
5. 看到 `UART receive-only capture armed` 后，给 UBOX10 接通原装电源。键盘输入只由电脑端脚本处理，绝不会写入串口。
6. 可以等待设定时间自动结束，也可以按 `Ctrl+C` 或 `Q` 安全停止。脚本仍会保存 `.raw.bin`、`.txt` 和 `uart-capture.json`，并把终止原因记录为 `ManualCtrlC` 或 `ManualQ`。普通采集不生成哈希；只有明确需要传输或长期归档校验时才添加 `-GenerateChecksums`。
7. 先不要分析或再次上电；把日志目录、接线照片和设备最终屏幕状态提供给项目负责人。

若出现“`-File` 的实际参数不存在”，表示 PowerShell 还没有找到脚本，采集尚未开始、串口也尚未打开。不要给 UBOX10 通电；回到第 4 步检查绝对路径。若出现端口格式错误，则说明仍使用了 `COMx` 占位符，必须替换为类似 `COM3` 的实际编号。

若完全无输出，先检查 GND、端口、焊点和 J21 TX→FT232RL RXD 是否正确。**不要立刻换波特率，更不要接 TXD/VCC。** 先归档 0-byte 结果和照片，经复核后才允许以新日志依次尝试 `1500000` 或 `921600`。

## 结果判读

| 现象 | 可能含义 | 安全下一步 |
|---|---|---|
| 可读的 BootROM/U-Boot 文本 | 成功获得早期启动链证据 | 保存完整日志；先分析而非发送命令。 |
| 乱码但持续输出 | 波特率、数据格式或电平不匹配 | 换波特率并单独保存日志；保持被动接线。 |
| 完全无输出 | TX/RX、GND、针脚、端口或启动路径未确认 | 复核丝印/接触；不改接 VCC/TX。 |
| 上电异常、异味、发热、显示异常 | 可能存在接线问题 | 立即断电、拔线；拍照记录，停止实验。 |

## 后续日志策略

优先采集**当前设备状态**的日志，因为它无需刷写。只有在官方回退过程已被单独评审且用户决定恢复官方固件后，才采集官方基线日志以做差分；恢复官方固件本身是严重风险操作，不属于本手册授权范围。
