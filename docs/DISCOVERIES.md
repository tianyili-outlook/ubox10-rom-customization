# 已确认的重要事实

- 官方固件是 Allwinner IMAGEWTY/PhoenixCard 容器，Android 12 Retrofit A/B dynamic partitions。
- `super` 包含 `system_a`、`product_a`、`vendor_a`、`vendor_dlkm_a`；当前镜像没有 `_b` 逻辑分区数据 extent。
- Fastboot 可通信：`992304568773 fastboot`，`getvar version` 返回 `0.5`；该实现不提供常见槽位变量。
- UART J21 的被动接收链路可用：COM3、115200 8N1，只接 GND 和板端 TX→FT232RL RXD。
- 历史候选 `x12-purified.img` 的 `system_a` 根目录层级错误，并含调试 boot/vendor_boot；禁止继续使用。
- 官方 `system_a` ext4 根包含 `/system`，语义清单共 3857 个条目、无解析错误。
- 官方 system 剩余空间很少，添加 APK 前应先删除不需要的应用或扩容。
- UBTunnel 位于 `/system/app/UBTunnel.6/UBTunnel.6.apk`，测试版 1 已只删除该目录。
- `ProxyHandler` 和 `VpnDialogs` 是 AOSP priv-app，不能仅凭名称当作厂商恶意组件。
- Wi‑Fi、蓝牙、以太网、CEC、遥控和音视频支持主要依赖官方 vendor/vendor_dlkm/boot 侧内容；测试版 1 未改这些分区。
- 测试版 1 的共同 ext4 条目全部保持一致，只有 UBTunnel 两个路径消失以及 `/system/app` 合法链接数变化。
- 测试版 1 构建时，AVB 整链、super 结构和 IMAGEWTY 载荷校验均通过；后续实机启动结果见下一项。
- 测试版 1 已实机启动成功；删除 UBTunnel 后 Google、YouTube、bilibili 主站和 API 均可访问。该结果证明当前固件构建链可用；但量产过程同时擦除了 metadata/userdata，因此只能确认“新基线不再出现问题”，不能把改善完全归因于 UBTunnel。
- PhoenixCard 量产日志在约 305 秒输出 `CARD OK`、`sprite success`，所有实际下载分区均完成写入/校验。
- 量产过程中主 GPT entry-array CRC 错误会回退使用 backup GPT，重写 GPT 后仍有同样提示；设备实际可启动，当前作为非阻塞已知现象保留。
- 以太网、蓝牙扫描和高码率 1080p/4K 播放已通过；CEC 与 BBLL 不作为当前必测项。
- Android 中打开 `USB debugging` 后，Windows 没有任何 USB 枚举，`adb devices -l` 为空；这发生在授权弹窗之前，不是 `Mock location app` 或 `Select debug app` 设置造成。

- Test9r1 从 Test8r2 增加 leanback、remoteprovider jar/XML、privapp allowlist、单资源 RRO 和本地官方原签名接收端，未修改 `vendor_dlkm`。语义检查确认 10 个预期新增路径、共同普通文件仅 `build.prop` 改变；ext4、AVB、super、IMAGEWTY 和 24 项单元测试套件通过。
- Test9r1 固件为 2,005,946,368 bytes，SHA-256 `38A0C232750ECD433B2783E0CFBFFC48C17071226EE2AEC978BE5AC6C12F6E33`。其离线结果是 PASS，后续真机结果已确认失败，见下两条。
- Test9r1 真机中 feature、shared library、Remote Service APK/版本和 `TV_VIRTUAL_REMOTE_CONTROLLER` 均正确，但 `pm path com.ubox10.overlay.tvremote`、overlay list 和 framework lookup 都为空；启动日志只扫描 system_ext/product 等 overlay 目录，Test9r1 的文件却在 `/system/overlay`。provider watcher 因 package 未设置/白名单化持续拒绝服务，6466/6467 未监听，因此手机无法发现是产品集成层确定性失败，不是手机或 WLAN 随机故障。
