# 风险登记册

| ID | 风险 | 等级 | 防护/恢复 |
|---|---|---:|---|
| R-001 | 错误 PhoenixCard 打包或写入导致无法启动 | 严重 | M1–M5 离线验证；先做完整恢复镜像和 UART 启动日志；未经恢复演练不刷写。 |
| R-002 | 修改 vbmeta/AVB 导致验证失败或启动循环 | 严重 | 先完整解析 AVB 链与密钥策略；禁止以禁用验证替代正确签名。 |
| R-003 | 删除表面“厂商应用”实则硬件依赖组件 | 高 | 对 APK、init、binder 服务、SELinux 和 HAL 建立依赖证据；采用逐项最小变更。 |
| R-004 | 动态分区元数据或分区组大小不一致 | 严重 | 用 lpdump/lpmake 校验；构建后重新解析并比对布局。 |
| R-005 | 网络问题并非厂商代理而是 DNS/TLS/地区策略 | 高 | 在删改前采集 DNS、路由、证书、iptables/eBPF（如有）及应用日志证据。 |
| R-006 | 原始镜像损坏、混淆或版本不一致 | 高 | 每步验证 SHA-256；保存来源、日期和副本位置；不覆盖原文件。 |
| R-007 | 缺少可用签名密钥 | 高 | 在 M2 明确 AVB 签名模型；若无法合法重签，暂停重打包路线，先评估可验证替代方案。 |

等级：低/中/高/严重。严重风险操作必须在开始前给出明确恢复方案并获得确认。
