# 风险登记册

| ID | 风险 | 等级 | 状态 | 防护/恢复 |
|---|---|---:|---|---|
| R-001 | Android 进入 Recovery 而非 System | 严重 | ⚠️ 开放 | 通过 ADB/UART/Recovery 日志收集诊断信息，确定 Recovery 触发源后再修改固件。 |
| R-002 | Recovery 无法操作（红外遥控无响应，USB 键盘无输入） | 高 | ⚠️ 开放 | 尝试 Recovery ADB、验证 USB OTG 模式、UART 串口诊断。 |
| R-003 | 根本原因尚未确定 | 严重 | ⚠️ 开放 | 遵循证据驱动调试原则，避免盲目修改固件引入额外变量。 |
| R-004 | 修改 vbmeta/AVB 导致验证失败或启动循环 | 严重 | ✅ 已缓解 | 使用 AOSP test-keys 完成重签名，AVB 链已验证通过。 |
| R-005 | 删除表面"厂商应用"实则硬件依赖组件 | 高 | ✅ 已缓解 | 已对 APK、init、binder 服务建立依赖证据；LED 控制组件已确认保留。 |
| R-006 | 动态分区元数据或分区组大小不一致 | 严重 | ✅ 已缓解 | super 重构后通过 lpdump 校验。 |
| R-007 | PhoenixCard 打包或写入导致无法启动 | 严重 | ✅ 已解决 | pack_image.py 1024 字节对齐修复后，烧录进度 100%。 |
| R-008 | 原始镜像损坏、混淆或版本不一致 | 高 | ✅ 已缓解 | SHA-256 校验；保存来源、日期和副本位置。 |

等级：低/中/高/严重。严重风险操作必须在开始前给出明确恢复方案并获得确认。
