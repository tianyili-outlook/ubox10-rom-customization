# 风险登记册

状态含义：**开放** 表示尚未消除；**部分缓解** 表示只具离线或局部证据；**已缓解** 需要对应的实机回归记录。严重风险操作必须在开始前给出明确恢复方案并获得确认。

| ID | 风险 | 等级 | 状态 | 防护、验证与恢复 |
|---|---|---:|---|---|
| R-001 | 设备进入 Recovery 而非 Android System | 严重 | 开放 | Fastboot 协议已验证但其变量不支持槽位/userspace，无法确认 Recovery 触发源、BCB 或第一个失败点；优先采集无修改 UART 冷启动日志。恢复路径是官方 PhoenixCard 镜像，未验证前不新增刷写。 |
| R-002 | Recovery 无输入，交互诊断受限 | 高 | 开放 | 红外、键盘、Recovery ADB 均不可用；标准 Fastboot 已可只读交互但不支持槽位/userspace 变量。优先被动 UART，不再叠加 Recovery ADB 修改。 |
| R-003 | 启动失败根因未知 | 严重 | 开放 | M6a 形成假设表；M6b 先做零内容重建；每次后续实验只验证一个变量。 |
| R-004 | AVB 根信任、描述符或 hashtree 不兼容 | 严重 | 开放 | 候选与原件存在公钥、hash 算法/FEC 差异；只接受启动链日志和单变量对照的放行，绝不使用 `--flags 2` 绕过。 |
| R-005 | 删除“厂商应用”时误删硬件依赖 | 高 | 部分缓解 | 静态依赖图和保留清单已建立，但 Wi-Fi、蓝牙、CEC、遥控、音视频尚未实机回归；每项删除保留可逆 manifest。 |
| R-006 | ext4 重建丢失符号链接、根目录或元数据 | 严重 | 开放 | 当前 `.symlink` 存根与元数据缺失已确认；先实现语义导出/比较和零内容 round-trip，不把现有重建物刷入设备。 |
| R-007 | PhoenixCard 可写入但 Android 仍不可启动 | 严重 | 部分缓解 | 100% 进度只证明容器被写入；每次候选必须在容器、super、ext4 三层独立校验，并保留官方回退介质。 |
| R-008 | 原始固件丢失、损坏或版本混用 | 高 | 已缓解 | 已记录 SHA-256 与容器基线；仍不得覆盖、重命名或以候选镜像替代原件。 |
| R-009 | 将 USB 线索或描述符误判为已可用协议 | 高 | 受控 | `FF/42/03`、`fastboot devices` 和 `getvar version → version: 0.5` 已完成协议证据链；这只授权 M6a 白名单读取，仍禁止 `flash`、`erase`、`download`、`boot`、`continue`、`reboot`、`set_active`、`oem`、`unlock`。 |
| R-010 | #11.1 将 boot、vendor_boot、init、SELinux 与 USB 多变量叠加 | 严重 | 开放 | 镜像隔离、暂停且未刷入；恢复条件是 M6a 通过、明确单变量假设和官方回退路径。 |
| R-011 | UART 接线损伤 I/O 或造成电源反灌 | 中 | 受控 | 仅使用 3.3V TTL 适配器，首次只接 GND 与板端 TX→适配器 RX；不接 VCC 或适配器 TX，拔线即可恢复。 |
| R-012 | 手工 USB INF 或 Zadig 造成主机驱动状态不可追溯 | 高 | 受控 | 已归档当前 libwdi `oem79.inf`、U1 备份和写后验证；不安装修改后的 Google INF，不关闭签名强制，不直接 Bind Zadig；当前变更仅追加目标 GUID，保留精确回滚文件。 |
| R-013 | 把 Google Play / GMS 视为可自由注入的 APK，导致授权、认证或兼容性失败 | 高 | 开放 | 仅保留并验证设备原有、合法授权的组件；不重分发受限软件。Play 可用性以实机登录、认证状态与功能回归为准。 |
| R-014 | GUID 试验误覆盖 Windows 主机既有接口注册 | 中 | 受控 | U1 已成功追加目标 GUID，写后确认原有三个 GUID 保留，且 Fastboot 枚举恢复；完整备份在 `logs/device/20260722-004314/guid-backup.json`。如需恢复，按同一备份精确回滚并物理拔插。它不写入设备存储。 |

等级：低 / 中 / 高 / 严重。
